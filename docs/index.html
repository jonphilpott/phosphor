Quick Start

Build

cmake -B build -DCMAKE_PREFIX_PATH=$(brew --prefix)
cmake --build build

Run

./build/phosphor -s scenes/test.lua

Once running, the engine is driven by keyboard — F fullscreen, Space pause, B blackout, T alignment grid, P parameters.

Everything the engine does by hand. Grouped by why you would reach for it — the output group is the one to know before a show.

Output — live safety

KeyAction
BBlackout. Output goes to black instantly. The scene keeps running and the feedback buffer keeps filling underneath, so restoring brings back a live image rather than a frozen one. This is the “something is wrong, kill the projector” key.
- / =Master output level down / up, in 10% steps. For venue brightness, and for not blinding a front row.
FToggle fullscreen on the current display. Viewport and Lua globals update immediately.

Transport — controlling time

KeyAction
SpacePause. The scene keeps redrawing with dt = 0, so feedback trails hold still rather than the screen going black, and anything driven by elapsed() freezes in place.
[ / ]Halve / double the rate time passes. Affects dt, elapsed() and u_time together. Clamped to ×1/64 … ×8.
\Back to ×1 speed, unpaused.

None of these touch the musical clock, which runs on the wall clock — pausing the visuals does not distort tempo or beat phase.

Scene Anatomy

A scene is a plain Lua file. The engine calls these optional global functions:

HookWhen calledTypical use
on_load()Once, after the file is executedAllocate canvases, load images, set initial shader
on_frame(dt)Every frame — dt is seconds since last frameClear, draw geometry, advance animation state
on_osc(addr, ...)Once per incoming OSC messageReact to live control from SuperCollider / PD
on_beat(phase)On each /beat OSC messageTrigger something musically — advance a pattern, fire a flash, step an automaton

All three are optional. A scene that defines none of them is valid (the window shows a “no scene loaded” message).

Built-in globals

NameTypeDescription
screen_widthintegerDrawable width in pixels (Retina-aware). Updated on resize and fullscreen toggle.
screen_heightintegerDrawable height in pixels.
persisttableA table whose contents survive a hot reload — see Hot reload below. Empty on first run.
elapsed()function → numberSeconds since startup — the same clock the engine sends to shaders as u_time, so Lua and shader animation stay in step. Responds to pause and the time-scale keys, which a scene’s own t = t + dt accumulator does not.

Minimal scene template

-- Copy-paste starting point

local t = 0

function on_load()
    shader_set("scanlines")
end

function on_frame(dt)
    t = t + dt
    clear(0, 0, 0, 1)
    set_color(0, 1, 0.4, 1)
    draw_circle(screen_width / 2, screen_height / 2, 60 + math.sin(t * 2) * 20)
end

Hot reload

Save the scene file while Phosphor is running — changes appear within ~200 ms. The Lua VM is torn down and rebuilt; GPU state (renderer and FBOs) is untouched. on_load() is called again after reload. The post-process shader chain is reset on reload, so a scene always starts from the pipeline its own on_load asks for rather than inheriting the previous scene’s.

Fragment shaders hot-reload too: save a file in shaders/ and the loaded programs recompile in place within ~250 ms, including the ones canvases own. If the edited source fails to compile, the previous program keeps running and the GLSL error is printed — a typo mid-set doesn’t drop the pass.

Keeping state across a reload

Reloading destroys the whole Lua VM, which is what makes it reliable — no stale globals, no half-updated closures. It also means a scene normally restarts from nothing on every save: a clock accumulating t = t + dt returns to zero, a particle field is rebuilt, a Game of Life grid that had been running for ten minutes is gone.

Anything stored in the global persist table survives instead. The idiom is to create state only if it is not already there:

function on_load()
    -- Runs on the first load; skipped on every reload after it, because
    -- persist.particles already exists.
    if not persist.particles then
        persist.particles = {}
        for i = 1, 300 do
            persist.particles[i] = { pos = vec(0, 0), vel = vec.random(50) }
        end
    end
    persist.t = persist.t or 0
end

function on_frame(dt)
    persist.t = persist.t + dt      -- keeps counting across saves
end

Now you can edit the drawing code, the forces, the colours — and the simulation carries on mid-flight instead of starting over. scenes/vector_test.lua is built around this; edit any constant in it while it runs.

What can and cannot cross

CrossesDoes not
Numbers (integer and float subtypes preserved), strings, booleans, vectors, and tables of those, nested up to 16 deep. Functions, coroutines, and every userdata except vec — canvases, images, sprite sheets, conway and wolfram objects. These own GPU textures, framebuffers or C buffers that are freed when the VM closes, so there is nothing honest to carry across.

Anything that cannot cross is dropped and reported on stderr rather than disappearing silently. Table cycles (persist.a.self = persist.a) are detected and dropped too. If you want an automaton’s grid to survive, copy it into a plain table with the get/set methods those types already provide.

When a scene errors

A runtime error in on_frame does not black out the window. The half-drawn frame is discarded, the last complete frame is put back up, and the error message is drawn across the top of the screen. Logging is throttled to once a second so the terminal stays readable. Fix the file, save, and the next good frame clears the banner. The same applies to a syntax error saved into the scene: the visuals hold on the last good frame while you sort it out.

Drawing API

All coordinates are in pixel space: (0, 0) is the top-left corner, +X rightward, +Y downward. All geometry goes through the current transform matrix (see Transform Stack).

Clear

SignatureDescription
clear(r, g, b, a)Fill the frame buffer with a solid colour. Call this at the start of on_frame unless you want feedback trails.

Colour state

Two independent colour registers. State persists across frames until changed.

SignatureApplies toDefault
set_color(r, g, b, a)draw_rect, draw_circle1, 1, 1, 1
set_stroke(r, g, b, a)draw_line, draw_point1, 1, 1, 1
set_stroke_weight(w)Line thickness / point size in pixels1.0
set_circle_segments(n)Tessellation for draw_circle32

HSV colour

RGB is how the hardware thinks; hue/saturation/value is how visuals think. “Rotate the hue over time” is one number going up in HSV, and an awkward three-channel dance in RGB.

SignatureDescription
hsv(h, s, v [, a])Returns r, g, b, a — four values, so it drops straight into anything that takes a colour.
set_color_hsv(h, s, v [, a])Shorthand for set_color(hsv(...)).
set_stroke_hsv(h, s, v [, a])Shorthand for set_stroke(hsv(...)).

All components are 0..1, matching every other colour call in the engine — hue is not in degrees. Hue wraps, so h = 1.25 and h = 0.25 are the same colour and you can feed an ever-increasing number straight in without wrapping it yourself. Saturation 0 gives grey at brightness v.

-- Hue cycling on the engine clock
set_color(hsv(elapsed() * 0.1, 0.9, 1))
draw_circle(cx, cy, 60)

-- A whole palette from one loop
for i = 0, 7 do
    set_color_hsv(i / 8, 0.85, 1)
    draw_rect(i * 60, 20, 50, 50)
end

-- hsv() composes with clear() too
clear(hsv(0.6, 0.4, 0.12))
Expansion rule hsv() returns four values, and Lua keeps all of them only in the last argument position. set_color(hsv(h, 1, 1)) is fine. set_color(hsv(h, 1, 1), 0.5) is not — that passes only the red channel and then 0.5. Pass alpha to hsv itself: hsv(h, 1, 1, 0.5).

Blend mode

set_blend(mode) controls how new pixels combine with what is already on screen. It resets to "alpha" at the start of every frame, like the colour registers, so a scene that wants another mode asks for it each frame.

ModeResultUse for
"alpha"src×a + dst×(1-a)Normal layering. The default.
"add"src×a + dstLight accumulates instead of replacing — overlapping strokes brighten toward white. This is how phosphor, neon and CRT beams actually behave, and it is the mode to reach for with draw_feedback.
"multiply"src×dstDarkening and tinting. White leaves the destination alone, black knocks it out.
"screen"src + dst×(1-src)Lightens like add, but approaches white gently rather than clipping hard.
function on_frame(dt)
    draw_feedback(0.92)          -- fade the previous frame

    set_blend("add")             -- strokes now glow where they cross
    set_stroke(0.1, 0.9, 0.5, 1)
    for i = 1, 40 do
        local a = elapsed() + i * 0.15
        draw_line(cx, cy, cx + math.cos(a) * 300, cy + math.sin(a) * 300)
    end
end

Bitmap Text

An 8×8 monochrome bitmap font built into the binary — no font file to load, no dependency. Glyphs are drawn as filled rectangles through the normal geometry path, which means text obeys set_color and the transform stack exactly like a rectangle does: it rotates, scales and nests inside push/pop.

API

draw_text(x, y, str [, scale])
ParameterDefaultDescription
x, y—Top-left corner of the first glyph, in pixel space.
str—The string to draw. \n returns to the starting x and drops one line.
scale1.0Multiplies both axes. A glyph occupies 8 × scale pixels square, so scale = 3 gives 24 px text.
text_width(str [, scale]) → number

Pixel width of the longest line in str — every character is 8 × scale wide, and \n starts the measurement again. Use it to centre or right-align, since the font is fixed-width and there is nothing else to measure.

Character set

Printable ASCII, 0x20 (space) to 0x7E (~). Bytes outside that range advance the cursor by one glyph without drawing anything, so a stray control character or a UTF-8 multi-byte sequence leaves gaps rather than garbage — there are no accented or non-Latin glyphs in the font.

Colour and transforms

Text uses the fill colour from set_color, not the stroke colour. Because it goes through the transform stack, this works as you would expect:

function on_frame(dt)
    clear(0, 0, 0, 1)

    -- Plain text, top-left
    set_color(0, 1, 0.4, 1)
    draw_text(20, 20, "PHOSPHOR", 3)

    -- Horizontally centred
    local label = "SIGNAL LOST"
    local w = text_width(label, 2)
    set_color(1, 0.3, 0.2, 1)
    draw_text(screen_width / 2 - w / 2, 100, label, 2)

    -- Multi-line: \n returns to the starting x
    set_color(0.6, 0.6, 0.6, 1)
    draw_text(20, 160, "CH 01  -12.4 dB\nCH 02  -09.1 dB\nCH 03  -- ", 2)

    -- Rotating, because it is geometry like anything else
    push()
        translate(screen_width / 2, screen_height / 2)
        rotate(elapsed())
        local t = "ROTATE"
        draw_text(-text_width(t, 4) / 2, -16, t, 4)
    pop()
end

Cost

Each glyph is emitted as one rectangle per horizontal run of lit pixels rather than one per pixel — a typical glyph row is two or three runs, so a character costs roughly 12–18 vertices instead of up to 384. Text-heavy scenes such as matrix.lua and datafield.lua are perfectly happy putting hundreds of characters on screen per frame, but a full screen of tiny text is still real geometry, not a texture blit.

The engine uses this same font itself for the “no scene loaded” message and the on-screen error banner.

See scenes/text_test.lua for a scene exercising every one of these features.

Transform Stack

The transform stack works like Processing's pushMatrix/popMatrix. Transforms are post-multiplied — they apply in the order you call them.

FunctionDescription
push()Save the current matrix. Pair every push() with a pop().
pop()Restore the matrix saved by the matching push().
translate(x, y)Move the origin by (x, y) pixels.
rotate(radians)Rotate counter-clockwise around the current origin.
scale(sx, sy)Scale around the current origin. Pass one value to scale uniformly.
-- Rotate a rectangle around its own centre
push()
    translate(cx, cy)   -- move origin to rect centre
    rotate(angle)       -- rotate around that point
    draw_rect(-hw, -hh, hw * 2, hh * 2)  -- draw centred at origin
pop()                   -- restore transform
Transform stack does not affect canvas or image draws canvas:draw(), img:draw(), and sheet:draw() use a separate GPU shader that bypasses the CPU transform matrix entirely. push/translate/rotate/scale have no effect on these calls. Use the angle parameter on those functions instead — see Canvas and Images & Sprites.
Feedback

Feedback blends the previous frame's final composited image over the current frame buffer. Call it before drawing geometry in on_frame — it acts as a persistent background that geometry is drawn on top of.

draw_feedback(alpha [, scale [, angle]])
ParameterDefaultEffect
alpha—Blend weight 0–1. Lower = faster fade. Required.
scale1.0Scale the previous frame around the screen centre. >1 = infinite zoom outward; <1 = shrinking spiral.
angle0.0Rotate the previous frame around the screen centre (radians). Non-zero = rotating trail.

Alpha decay reference (at 60 fps)

alphaHalf-lifeCharacter
0.90~0.4 sFast phosphor decay
0.95~1.0 sMedium trail
0.97~1.6 sLong smear
0.99~5.0 sGhost persistence
function on_frame(dt)
    -- No clear() — feedback IS the background
    draw_feedback(0.93, 1.002, 0.002)   -- slow zoom + slow rotate = spiral trail

    set_color(1, 1, 1, 1)
    draw_circle(math.random() * screen_width,
                math.random() * screen_height, 8)
end
Tip Omitting clear() entirely and relying on feedback gives the classic CRT phosphor look. Adding a very dark clear(0,0,0,0.03) as an FBO blend is not directly supported — use alpha < 1.0 on draw_feedback instead.
Post-Process Shader Pipeline

Post-process shaders run on the full frame after geometry is drawn. Shaders are chained: the output of each feeds the next. The pipeline is applied once per frame, in end_frame().

FunctionDescription
shader_set(name, ...)Replace the entire pipeline. Pass multiple names to chain them left-to-right.
shader_add(name)Append one shader to the current pipeline.
shader_clear()Remove all post-process shaders.
shader_set_uniform(name, value)Set a named float uniform on all active shaders.
Common mistake Calling shader_set twice sets only the last pipeline. To chain two shaders, pass both names to a single call:
shader_set("scanlines", "chromatic_ab")

Writing a Custom Shader

Place fragment shader files in shaders/<name>.frag relative to the working directory. Load with shader_set("name") — no extension, no path.

Required preamble

#version 330 core

uniform sampler2D u_texture;
uniform vec2      u_resolution;
uniform float     u_time;
uniform float     u_beat;

in  vec2 v_uv;
out vec4 frag_color;

Minimal passthrough

#version 330 core
uniform sampler2D u_texture;
in  vec2 v_uv;
out vec4 frag_color;

void main() {
    frag_color = texture(u_texture, v_uv);
}

Example: greyscale with vignette

#version 330 core
uniform sampler2D u_texture;
uniform vec2      u_resolution;
in  vec2 v_uv;
out vec4 frag_color;

void main() {
    vec4 c = texture(u_texture, v_uv);
    float grey = dot(c.rgb, vec3(0.299, 0.587, 0.114));

    // Vignette: darken corners
    vec2 uv = v_uv * 2.0 - 1.0;
    float vig = 1.0 - dot(uv, uv) * 0.4;

    frag_color = vec4(vec3(grey * vig), c.a);
}

Custom uniforms from Lua

CallSets
shader_set_uniform(name, x)float
shader_set_uniform(name, x, y) or (name, vec)vec2
shader_set_uniform(name, x, y, z [, w])vec3 / vec4
shader_set_data(name, table)sampler2D — see below

canvas:set_uniform and canvas:set_data are the canvas-local equivalents.

Arrays as data textures

A uniform carries at most four numbers. A spectrum, an envelope curve or a per-element value is hundreds, and only a texture can be indexed per fragment. shader_set_data uploads a Lua array as a one-row float texture:

-- Lua
local bands = {}
for i = 1, 64 do bands[i] = level_for_band(i) end
shader_set_data("u_bands", bands)
// GLSL
uniform sampler2D u_bands;
float band = texture(u_bands, vec2(v_uv.x, 0.5)).r;

Sampling is nearest-neighbour and clamped at the edges — this is data, not an image, so interpolating between adjacent elements would invent values that were never measured.

Custom float uniforms from Lua

-- In Lua:
shader_set("my_shader")
shader_set_uniform("u_my_value", 0.5)

-- In GLSL:
uniform float u_my_value;
Note Shaders are reloaded from disk each time shader_set() or shader_add() is called. You can edit a .frag file and call shader_set from the scene to hot-reload it.
Noise Functions

Classic Perlin noise (Ken Perlin's 2002 improved permutation table). All functions return values in [−1, 1].

SignatureDescription
noise(x)1-D Perlin noise
noise(x, y)2-D Perlin noise
noise(x, y, z)3-D Perlin noise
fbm(x, y [, octaves [, lacunarity [, gain]]])Fractal Brownian Motion — stacked octaves of noise

fbm defaults

ParameterDefaultEffect
octaves6Number of noise layers (1–16)
lacunarity2.0Frequency multiplier per octave
gain0.5Amplitude multiplier per octave
Performance note Noise is a Lua→C call with moderate overhead. Calling it for every pixel of a full-screen grid (e.g. step = 4) will drop below 60 fps on large Retina displays. Use a larger step (12–24 px) for realtime visualisations, or write a custom GLSL shader for full-resolution noise fields — the GPU runs noise at native speed. 
-- Scrolling 2-D noise field
local scale = 0.006
local t = 0

function on_frame(dt)
    t = t + dt * 0.4
    clear(0, 0, 0, 1)
    local step = 18
    for y = 0, screen_height - 1, step do
        for x = 0, screen_width - 1, step do
            local n = noise(x * scale + t, y * scale) * 0.5 + 0.5
            set_color(n, n * 0.8, n * 0.3, 1)
            draw_rect(x, y, step, step)
        end
    end
end
Easing & Math Utilities

Seven math primitives available as global functions in every scene — no dofile or require needed. They cover the most common animation and control-rate tasks: interpolation, frame-rate-independent smoothing, range mapping, and beat-sync pulses.

Interpolation

SignatureDescription
lerp(a, b, t)Linear interpolation. Returns the value t of the way from a to b. t=0 → a, t=1 → b. Not clamped — pass t outside [0,1] to extrapolate.
smoothstep(t)S-curve: maps t in [0,1] to [0,1] with zero derivative at both ends. Formula: 3t²−2t³. Input is clamped automatically. Use this instead of lerp when you want eased start and end rather than a linear ramp.

Exponential smoothing

Both functions move a value toward a target in a frame-rate-independent way — unlike lerp(current, target, k) called each frame, which moves twice as far at 30 fps as at 60 fps.

SignatureDescription
smooth(current, target, rate, dt)Rate-based smoother. Each frame the remaining gap is multiplied by e−rate·dt. Higher rate = snappier response. Rule of thumb: rate 1 ≈ 63% of gap closed per second; rate 5 ≈ 99%; rate 10 ≈ nearly instant.
smooth_hl(current, target, half_life, dt)Half-life smoother. The gap halves every half_life seconds — more intuitive when thinking in musical time. half_life = 0.1 is snappy; 2.0 is a lazy drift. Returns target immediately if half_life ≤ 0.

Range & clamping

SignatureDescription
map(x, in_lo, in_hi, out_lo, out_hi)Remaps x from [in_lo, in_hi] to [out_lo, out_hi]. Not clamped — use clamp() afterwards if you need hard limits. Typical use: converting OSC 0..1 values to pixel coordinates.
clamp(x, lo, hi)Constrains x to [lo, hi]. Equivalent to math.max(lo, math.min(hi, x)) but reads as intent rather than idiom.

Beat pulse

SignatureDescription
pulse(t, bpm, width)Returns a 0..1 value that peaks at 1 on each beat and fades smoothly to 0 within width seconds of the beat. Good for flash and strobe effects driven by a time accumulator. width is the half-window in seconds — try 0.05–0.1 for a tight flash.

Choosing smooth() vs smooth_hl()

smooth()smooth_hl()
Parameterrate (nepers/sec)half_life (seconds)
Snappyrate 10–20half_life 0.05–0.1
Mediumrate 4–7half_life 0.2–0.4
Lazyrate 1–2half_life 1.0–2.0
Best forControl-rate intuitionMusical / tempo-relative intuition
local t    = 0
local pos  = 0        -- current smoothed value
local bpm  = 120

function on_frame(dt)
    t = t + dt

    -- map(): OSC 0..1 → pixel x; clamp() guards against out-of-range input
    local target = clamp(map(some_osc_value, 0, 1, 0, screen_width), 0, screen_width)

    -- smooth(): snappy follow at rate 8
    pos = smooth(pos, target, 8, dt)

    -- smoothstep(): use distance to target as an eased size modulator
    local dist_frac = clamp(map(math.abs(pos - target), 0, 400, 0, 1), 0, 1)
    local radius    = lerp(10, 50, smoothstep(dist_frac))

    -- pulse(): beat-sync flash — 120bpm, 70ms window
    local flash = pulse(t, bpm, 0.07)
    clear(flash * 0.1, flash * 0.07, flash * 0.03, 1)

    set_color(0.3, 1.0, 0.5, 1)
    draw_circle(pos, screen_height / 2, radius)
end
See also scenes/easing_demo.lua — a live showcase scene that puts all seven functions on screen simultaneously: four dots chasing a drifting target at different smoothing rates, with a beat-sync background pulse and OSC control.
Vectors

A 2D vector type in the spirit of Processing’s PVector, implemented in C as userdata. Positions, velocities, forces and directions are the natural unit of animation, and writing them as pairs of loose x/y numbers is where most scene code goes to die.

Construction

SignatureDescription
vec(x, y)A vector. Both components default to 0, so vec() is the origin.
vec.new(x, y)Identical — vec(...) is shorthand for it.
vec.from_angle(a [, len])Unit vector at angle a radians, scaled to len (default 1).
vec.random([len])Uniformly distributed random direction, length len (default 1). Uses math.random, so math.randomseed makes it reproducible.

v.x and v.y are readable and writable. Assigning any other field is an error rather than silently doing nothing, which catches typos immediately.

Operators

a + b, a - b, -aComponent-wise, new vector.

a * b, a / bComponent-wise, not the dot product. Useful for non-uniform scaling: p * vec(screen_width, screen_height) maps a 0..1 position onto the screen. For the dot product use a:dot(b).

v:smooth_hl(u, hl, dt)v:smooth_hl_(u, hl, dt)The same, parameterised by half-life in seconds.

Anywhere a vector argument is accepted, two numbers work as well: p:add_(v) and p:add_(0, 9.8) are both valid, which saves building a temporary just to add a constant.

smooth() is the one to remember

Almost everything that follows something else — a camera trailing a subject, a value chasing an OSC parameter, an attractor being pursued — wants this. Chasing a target with v:lerp(target, 0.1) every frame moves twice as far at 30fps as at 60fps; smooth closes a fixed proportion of the gap per second and does not care how the frame rate wanders.

-- rate 1 closes ~63% of the gap per second; 5 is snappy; 10 nearly instant
persist.cursor:smooth_(target_x, target_y, 4, dt)

Allocation

Every operator returns a new vector, so a + b allocates. For a few hundred operations a frame that is irrelevant, and the readable form is the right default. A particle system doing several thousand a frame generates enough garbage that Lua’s collector will eventually show up as a frame-time spike — which is what the in-place methods are for. Write it readably first; convert the hot loop only if you measure a problem.

-- Readable: one new vector per operation
local steer = (target - p.pos):normalize() * FORCE * dt
p.vel = (p.vel + steer):limit(MAX_SPEED)

-- Allocation-free: same result, one scratch vector reused for every particle
steer:set_(target):sub_(p.pos):normalize_():scale_(FORCE * dt)
p.vel:add_(steer):limit_(MAX_SPEED)
p.pos:add_(p.vel.x * dt, p.vel.y * dt)
Vectors and draw calls Draw functions take plain numbers — draw_circle(p.x, p.y, r). v:xy() expands to two values, but Lua keeps multiple returns only in the last argument position, so draw_line(a.x, a.y, b:xy()) works while draw_circle(p:xy(), r) does not — the latter passes (x, r).

Vectors are also one of the few types that survive a hot reload, so a field of them can be kept in persist and go on moving while you edit the code around it. See scenes/vector_test.lua.

Wolfram 1D Cellular Automata

A Wolfram elementary cellular automaton is a 1D row of binary cells that evolves one generation at a time. Each cell's next state is determined by a 3-bit neighbourhood (left, centre, right) looked up in an 8-bit rule number (0–255). The engine keeps a ring buffer of the last N rows so you can draw the full history scrolling upward — oldest row at the top, newest at the bottom.

Constructor

ParameterDefaultDescription

width—Number of cells per row. Edges wrap (toroidal), so the automaton behaves as a ring — no boundary artefacts.
rows256History ring buffer depth. Older generations past this limit are silently overwritten.

ca:randomize()Clear the buffer and fill the initial row with random 0/1 values. Good for chaotic rules like 30.
ca:step()Compute one new generation from the current newest row and advance the ring buffer head. Call once per frame to scroll in real time.
ca:draw(x, y [, cell_w [, cell_h]])Draw all stored history rows from oldest (top) to newest (bottom) as filled rectangles. Uses the current set_color() fill. cell_w and cell_h default to 4.0.

Conway's Game of Life

A 2D cellular automaton using the classic B3/S23 rule set: a dead cell with exactly 3 live neighbours is born; a live cell with 2 or 3 live neighbours survives; all other cells die. The grid wraps toroidally — left/right and top/bottom edges connect — so gliders and other patterns travel indefinitely without hitting a wall.

The engine maintains two identically-sized buffers (current and next generation) in C and swaps them in O(1) after each step, so the Lua side sees a clean live/dead state without any partial-update artefacts.

Constructor

conway.new(width, height) → userdata
ParameterDefaultDescription
width—Grid width in cells.
height—Grid height in cells.

Methods

SignatureDescription
ca:randomize([density])Fill the grid randomly. density is the fraction of cells that start alive (0.0–1.0, default 0.35). A random soup at ~35% usually evolves into a stable mix of still lifes, oscillators, and gliders within a few hundred generations.
ca:clear()Set all cells to dead. Useful before stamping a pattern in via ca:set().
ca:step()Compute one full generation of B3/S23 and swap buffers. Call once per frame for real-time simulation, or multiple times per frame to fast-forward.
ca:draw(x, y [, cell_w [, cell_h]])Draw all live cells as filled rectangles using the current set_color() fill. cell_w and cell_h default to 4.0. Dead cells are not drawn, so the background shows through.
ca:get(x, y)Return 0 or 1 for the cell at column x, row y (both 1-indexed) in the current generation.
ca:set(x, y, v)Write 0 or 1 into column x, row y (both 1-indexed). Takes effect immediately — the next ca:step() will use the written value.
Indexing convention All coordinates are 1-indexed, consistent with Lua conventions. Column 1 is the leftmost cell; row 1 is the topmost cell. A grid created with conway.new(cols, rows) has valid x in [1, cols] and y in [1, rows].

Reading state for custom rendering

ca:draw() is the fast path, but ca:get() lets you read individual cells and apply your own colour logic — for example, fading newborn cells from white to green using an age counter, as in everything_test.lua.

-- Custom rendering: colour cells by age
local age = {}
for i = 1, cols * rows do age[i] = 0 end

-- Inside on_frame, after ca:step():
for r = 1, rows do
    for c = 1, cols do
        local i = (r - 1) * cols + c
        if ca:get(c, r) == 1 then
            age[i] = age[i] + 1
            local t = math.min(age[i] / 8.0, 1.0)   -- 0 = newborn, 1 = aged
            set_color(1.0 - t * 0.8, 1.0, 1.0 - t * 0.6, 1)
            draw_rect((c-1) * cell_w, (r-1) * cell_h, cell_w - 1, cell_h - 1)
        else
            age[i] = 0
        end
    end
end

Canvas

A canvas is an offscreen render target (FBO pair) with its own optional local shader chain. Render geometry into it, apply shaders scoped only to that canvas, then composite the result into the main scene.

Allocate canvases in on_load() or at the top level of the scene — not inside on_frame(). Creating an FBO pair every frame leaks GPU memory.

API

SignatureDescription
canvas.new(w, h)Allocate an offscreen canvas at w × h pixels. Returns a Canvas userdata.
canvas:begin()Redirect all subsequent draw calls into this canvas. Pushes the render-target stack.
canvas:finish([shader, ...])Flush geometry, optionally run a local shader chain, pop the render-target stack. Zero or more shader names can be passed.
canvas:draw(x, y [, w, h [, angle]])Blit the canvas result into the current scene. w/h default to canvas size. angle rotates around the draw rect's centre (radians).
canvas:set_uniform(name, value)Set a named float uniform on this canvas's local shader pipeline. Must be called before canvas:finish(). See Fractal Shaders for the primary use case.
canvas:width(), canvas:height()Canvas dimensions in pixels.
Transform stack bypass canvas:draw() uses draw_image() internally and runs through a dedicated GPU shader. push/translate/rotate/scale have no effect on canvas draws. The angle parameter is the only way to rotate a canvas when compositing it. Position and scale are controlled by the x, y, w, h arguments.

Frame flow

function on_frame(dt)
    -- Draw into canvas
    c:begin()
        clear(0, 0, 0, 1)
        set_color(1, 0.4, 0.1, 1)
        draw_circle(c:width()/2, c:height()/2, 80)
    c:finish("chromatic_ab")    -- chromatic_ab applied only to this canvas

    -- Composite into main scene
    clear(0, 0, 0, 1)
    c:draw(100, 50, 400, 300, math.sin(t) * 0.3)   -- positioned, scaled, rotated
end

Canvases nest

A canvas:begin() inside another canvas's begin()/finish() block works correctly — the render-target stack handles save/restore automatically.

Local shader chain

Shaders passed to canvas:finish() are scoped to that canvas only — they do not affect the rest of the scene. The main post-process pipeline (set with shader_set()) runs afterwards on the full composited frame.

Waveforms

Two layers of waveform support: value functions that return a float for use as a modulator, and a renderer that draws a waveform as a polyline into the scene.

In all functions, t is a phase in cycles — 0 = start of period, 1 = one full period, 2 = two periods. Passing t * freq gives you freq oscillations per second.

Value functions — return float in [−1, 1]

SignatureShape

wave_square(t [, duty])+1 for the first duty fraction of the period, then −1. duty defaults to 0.5. Clamped to 0.01–0.99.
wave_tri(t)Rises −1→+1 in first half-period, falls back in second. Softer than saw.

    draw_waveform("sine", 0, screen_height * 0.6, screen_width, 120, 3, t)

Fractal Shaders

Two built-in fractal fragment shaders. Both ignore u_texture entirely — they generate the full image from the uniforms and u_time. They are most useful as:

  • Full-screen post-process: shader_set("mandelbrot") — replaces the frame entirely.
  • Canvas-local: render into a canvas via canvas:finish("julia") with uniforms set via canvas:set_uniform(), then composite the canvas into a larger scene.
Important If you use a fractal shader in canvas:finish() without calling canvas:set_uniform("u_zoom", ...), u_zoom defaults to 0 in GLSL. The shader clamps it to 0.0001, which maps the entire Mandelbrot/Julia set onto a microscopic region — the result is a near-uniform colour. Always set u_zoom to at least 1.0.

Musical Clock

/beat arrives as discrete events, which lets a scene flash on a beat but not be driven by one. A rotation completing exactly once per bar, an envelope decaying over an eighth note, a value easing across two beats — none of those can be expressed by a number that only changes two or three times a second.

So the engine watches when /beat messages arrive, infers the tempo from the gaps between them, and exposes a phase that advances continuously in between. Musical time becomes something you can read every frame.

FunctionReturns
bpm([n])Get the tempo in force, or set it directly. Returns 0 when nothing is known yet. See below.
beat_phase()Position within the current beat, [0,1), advancing every frame.
bar_phase()Position within the bar, [0,1). Combines whole beats counted with the fraction through the current one, so it sweeps rather than steps.
beat_count()Beats since the first message.
beats_per_bar([n])Get, or set and get. Default 4.
beat_active()True while beats are actually arriving — use it to fall back to elapsed() when the clock goes quiet.
beat_reset()Put the downbeat here — the bar starts now. How a scene with a manual tempo says where “one” is.
visual_latency([s])Shift visual timing to compensate for projector or capture delay.

Setting the tempo yourself

bpm(n) sets the tempo directly, so beat_phase() and bar_phase() run with no OSC source at all — for a tempo-synced piece with no clock to follow, or when you already know the tempo and would rather state it than have it inferred.

function on_load()
    bpm(128)              -- runs from here whether or not anything is connected
    beats_per_bar(4)
end

function on_frame(dt)
    rotate(bar_phase() * math.pi * 2)
end

With a manual tempo set, incoming /beat messages no longer change the rate — but they still re-align the downbeat. That combination is useful in itself: the message says where the beat is, your scene says how fast the beats go. bpm(0) hands the rate back to inference.

Changing tempo does not move the phase. The clock is re-anchored so the current position is preserved and only the rate changes from that point, making a tempo change a smooth acceleration rather than a visible snap.

rotate(bar_phase() * math.pi * 2)          -- exactly one turn per bar
local pulse = 1.0 - beat_phase()           -- ramp down across each beat
if not beat_active() then t = elapsed() end

Envelopes

Triggered decays, for anything that should fire on an event and fade:

FunctionEffect
env_trigger(name)Start (or restart) a named envelope at full level.
env(name [, half_life])Its current value, 0..1, decaying exponentially since the last trigger. Default half-life 0.15s. A name never triggered reads 0.

The name is the only state, so an envelope can be triggered in one place and read in another without the scene tracking anything:

on("/kick",  function() env_trigger("kick")  end)
on("/snare", function() env_trigger("snare") end)

function on_frame(dt)
    local flash = env("kick", 0.12)
    set_color(hsv(0.6, 0.5, 0.3 + flash * 0.7))
    draw_circle(cx, cy, 80 + env("snare", 0.2) * 60)
end

How the tempo is inferred

The gaps between the last eight /beat messages are taken and the median used, not the mean — messages arrive over UDP on a machine also doing graphics, so one being 30ms late is normal, and a median ignores a minority of bad samples entirely where a mean would be dragged by every one of them. Gaps outside 20–400 BPM are rejected as noise; a very long gap clears the estimate rather than averaging across a silence.

The clock free-runs at the tempo in force, so a dropped packet does not stall the visuals — phase, beat count and bar position all keep advancing and re-sync when the next beat lands. Tempo and phase live outside the Lua VM, so saving a scene mid-set does not restart the clock.

Only the gap between two real beats is measured. The first beat after startup, after a tempo change or after beat_reset() is measured against an anchor placed at an arbitrary point in the bar, so it is used to align the clock but contributes nothing to the tempo estimate.

Shaders receive the continuous phase as uniform float u_beat_phase, alongside the raw u_beat value.

OSC

Phosphor listens on UDP port 9000. Multiple clients (SuperCollider, Pure Data, TouchOSC, Max) send to the same port simultaneously — UDP is connectionless.

Incoming messages are dispatched on the main thread once per frame. The on_osc hook is called once per message.

ArgumentTypeDescription

...numbers / stringsOSC int and float arguments arrive as Lua numbers; OSC strings arrive as Lua strings. Zero or more.

Example

function on_osc(addr, ...)
    local args = {...}
    if addr == "/color" then
        r, g, b = args[1], args[2], args[3]
    elseif addr == "/speed" then
        speed = args[1] or speed
    elseif addr == "/bang" then

// Single message
~p.sendMsg("/color", 1.0, 0.0, 0.5);

// Routine for continuous control
(
r = Routine({
    loop {
        ~p.sendMsg("/speed", rrand(0.5, 2.0));
        0.5.wait;
    };
}).play(AppClock);
)
r.stop;

on(address, handler) — events

Register a function per address instead of growing an if/elseif ladder inside on_osc. Arguments arrive named rather than as args[1], args[2]:

on("/left_vu", function(level, index)
    local n = grid[index]
    n.colour = {0, 1, 1}
    n:target(level * 0.2)
end)

on("/scroll", function(dx, dy) ... end)
on("/kick",   function() env_trigger("kick") end)

Adding an address never touches existing code. Handlers are Lua functions, so they are re-registered on every reload — which happens by itself, since on() calls sit at the top level or in on_load. Registering the same address twice replaces the handler.

param(name, default [, min, max]) — values

Declares and reads in one call, so it can live exactly where the value is used and is safe to call every frame:

function on_frame(dt)
    local alpha  = param("feedback_alpha", 0.0, 0, 1)
    local scroll = param("scroll", vec(0, 0))

    draw_feedback(0.8 + alpha)
    translate(scroll.x, scroll.y)
end

The parameter listens on /<name>, and the default’s type decides how many OSC arguments it consumes:

DefaultConsumesExample message
1.0 (number)1 float/speed 1.5
vec(0, 0)2 floats/scroll 10 -4
{0.2, 0.8, 0.4}N floats/color 1.0 0.2 0.6
"default" (string)1 string/preset "warm"
false (boolean)1 int or float/invert 1

A message of the wrong arity or the wrong types is ignored rather than half-applied, so a bad message can never leave a value inconsistent. min and max clamp incoming values.

Which wins after a reload

Parameter values live outside the Lua VM, so they survive a reload. The rule is that the file wins until OSC takes over: a parameter follows the default written in your source — so editing that default and saving does what you expect while iterating — until a message arrives for it, after which the live value sticks and a save will not stomp it mid-set. Press 0 to clear every live value and fall back to the file defaults.

Nothing is consumed Both on() and param() observe messages without swallowing them — everything still reaches on_osc. Adding a parameter or a handler can never silently change how an existing scene behaves. Declared addresses are printed at startup so you know what to send.

Engine-level address

One OSC address is handled by the engine itself and is never forwarded to on_osc. It works even if the current scene defines no on_osc — or has crashed.

AddressArgumentEffect
/beatfloat or int — phaseSets u_beat for every shader in the pipeline and fires the optional on_beat(phase) hook. The value is whatever your clock sends: the common conventions are a [0..1) position within the bar, or a raw incrementing beat counter.
No scene switching over OSC There is deliberately no OSC address for loading a scene. A scene is arbitrary Lua with the full standard library behind it, os.execute included, so an address that loaded one would be remote code execution for anyone who could reach the port. Scenes are chosen with -s at launch and changed by editing the file, which hot reload picks up. 
-- SuperCollider: drive u_beat and on_beat from the transport
~p = NetAddr("127.0.0.1", 9000);
TempoClock.default.schedAbs(TempoClock.default.nextBar, {
    ~p.sendMsg("/beat", 0.0); nil
});
Note If on_osc is not defined in the scene, all non-engine messages are silently discarded.
